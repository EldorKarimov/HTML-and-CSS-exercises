Muammo: "Mening kompyuterimda ishlaydi!"

Siz Django loyihangizni yozdingiz. Kompyuteringizda hammasi zo'r ishlaydi. Keyin serverdagi hamkasbingiz kodni olib ishga tushirmoqchi bo'ladi va... 

# Sizning kompyuteringizda
Python 3.12, PostgreSQL 16, pip install -r requirements.txt ✅

# Hamkasbingizning kompyuterida
Python 3.9, PostgreSQL 14, pip install -r requirements.txt ❌
ERROR: Could not find a version that satisfies the requirement...

Bu muammo har bir dasturchi hayotida bor. Python versiyasi boshqa. PostgreSQL versiyasi boshqa. OS boshqa. Kutubxonalar boshqa versiyada. Hatto bitta kompyuterda ikki xil loyiha bir-biriga to'sqinlik qiladi — biri Python 3.9 so'raydi, boshqasi 3.12.

🐍 Django developerlarga tanish muammo

virtualenv bu muammoni qisman hal qiladi — faqat Python paketlarini ajratadi. Lekin PostgreSQL, Redis, OS kutubxonalari, libpq-dev, libjpeg kabilar — bular venv ichida emas. Docker hammasini birga qadoqlaydi.

Docker yechim: Dastur + Python + PostgreSQL + barcha kutubxonalar = bitta "quti" (container). Bu qutini kim ochsa — bir xil natija oladi. Sizning kompyuteringizda, serverda, hamkasbingizda — farqi yo'q.

Container vs Virtual Machine

"Quti" degan so'z eshitganda Virtual Machine (VirtualBox, VMWare) esga tushishi mumkin. Lekin container butunlay boshqa narsa. Farqini tushunish — Docker'ni tushunishning yarmi.

🏠
Virtual Machine = Alohida uy qurish Har bir dastur uchun alohida uy qurasiz: poydevor, devor, tom, mebel. Har bir uyning o'z elektr tizimi, suv tizimi bor. Xavfsiz, lekin juda og'ir — bitta uy qurish 5-10 minut, 2-4 GB joy oladi.
🏢
Container = Bitta binodagi alohida xonalar Bitta binoning elektr va suv tizimidan foydalanasiz (host OS kerneli). Har bir xona (container) alohida eshikka ega — biri boshqasiga kira olmaydi. Lekin yangi xona ochish 1-2 soniya, 50-200 MB joy.
Virtual Machine Container
Ishga tushish 1-5 daqiqa 1-2 soniya ⚡
Hajmi 2-10 GB 50-500 MB
OS To'liq OS (o'z kerneli) Host OS kernelini ishlatadi
Izolyatsiya To'liq (alohida uy) Process darajasida (alohida xona)
Nechta? Bitta serverda 5-10 ta Bitta serverda 50-100+ ta
💡 Xulosa

VM — butun OS ni ko'chiradi. Container — faqat dastur va uning kutubxonalarini oladi, OS kernelini esa kompyuterdan "qarz" oladi. Shuning uchun container tez va yengil.

📄 Dockerfile — bu retsept

Oddiy matnli fayl. Ichida yozilgan: qaysi OS olish, qaysi paketlarni o'rnatish, kodlarni qayerga ko'chirish, qanday buyruq bilan ishga tushirish. Django developer uchun bu requirements.txt + o'rnatish skripti birlashgani deb tasavvur qiling. 

Dockerfile
FROM python:3.12-slim        # Bazaviy image: Python 3.12
WORKDIR /app                    # Ish papkasi
COPY requirements.txt .          # Faylni ko'chirish
RUN pip install -r requirements.txt  # Paketlarni o'rnatish
COPY . .                          # Barcha kodni ko'chirish
CMD ["python", "manage.py", "runserver", "0.0.0.0:8000"]

📦 Image — bu tayyor quti

Dockerfile'dan docker build buyrug'i bilan Image yasaladi. Image — o'zgarmas (read-only) shablon. Uni bir marta yasab, istalgan joyda ishlatsa bo'ladi. Xuddi .iso fayl yoki setup.exe kabi — o'zi ishlamaydi, lekin undan ishlovchi narsani yaratsa bo'ladi. 

# Image yasash
$ docker build -t my-django-app .
#              ↑ nom berish       ↑ joriy papkadan

🚀 Container — bu ishlab turgan nusxa

Image'dan docker run buyrug'i bilan Container yaratiladi. Container — Image'ning tirik nusxasi. Bitta Image'dan 10 ta, 100 ta container ishga tushirsa bo'ladi — xuddi bitta .exe fayldan bir nechta oynani ochganday. 

# Container ishga tushirish
$ docker run -p 8000:8000 my-django-app
#           ↑ port ulash    ↑ qaysi image'dan
🔄 Django tilida aytganda

Dockerfile = requirements.txt + deploy skripti
Image = Tayyor server snapshoti (Python, paketlar, kod — hammasi ichida)
Container = python manage.py runserver ishlab turgan holat

Docker o'rnatish

Docker ikki ko'rinishda keladi: Docker Desktop (Windows/Mac uchun grafik interfeys bilan) va Docker Engine (Linux uchun faqat terminal). Ikkalasi ham bir xil docker buyruqlarini ishlatadi.

1

Windows / Mac

docker.com/products/docker-desktop sahifasidan yuklab o'rnating. O'rnatgandan keyin Docker Desktop ilovasini ishga tushiring — u fonda ishlaydi.

2

Linux (Ubuntu/Debian)

# Eski versiyalarni o'chirish
$ sudo apt remove docker docker-engine docker.io containerd runc

# Docker rasmiy repozitoriyasini qo'shish
$ sudo apt update
$ sudo apt install ca-certificates curl gnupg
$ sudo install -m 0755 -d /etc/apt/keyrings
$ curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
$ echo \
  "deb [arch=$(dpkg --print-architecture) \
  signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo $VERSION_CODENAME) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Docker'ni o'rnatish
$ sudo apt update
$ sudo apt install docker-ce docker-ce-cli containerd.io docker-compose-plugin

# sudo siz ishlatish uchun
$ sudo usermod -aG docker $USER
# Keyin logout/login qiling
3

Tekshirish

$ docker --version
Docker version 27.x.x, build xxxxxxx

$ docker run hello-world
Natija
Hello from Docker! This message shows that your installation appears to be working correctly. ...

Agar hello-world muvaffaqiyatli chiqsa — Docker ishlayapti!

Birinchi amaliyot: container ichida Python

Keling, Docker'ning kuchini ko'ramiz. Sizning kompyuteringizda Python 3.9 bo'lsin. Lekin sizga hozir Python 3.12 kerak — o'rnatmasdan, hech narsa buzmasdan. 

# Python 3.12 container ichida ishga tushirish
$ docker run -it python:3.12-slim
#            ↑  interactive + terminal
Natija
Unable to find image 'python:3.12-slim' locally 3.12-slim: Pulling from library/python ... Status: Downloaded newer image for python:3.12-slim Python 3.12.x (main, ...) [GCC 12.2.0] on linux Type "help", "copyright", "credits" or "license" >>>

Siz hozir container ichidasiz! Bu sizning kompyuteringiz emas — bu alohida Linux muhiti, ichida Python 3.12 o'rnatilgan. Sinab ko'ring: 

# Container ichida
>>> import sys
>>> sys.version
'3.12.x ...'

>>> import os
>>> os.listdir('/')
['bin', 'boot', 'dev', 'etc', 'home', 'lib', ...]  # Linux!

>>> exit()  # Containerdan chiqish
💡 Nima sodir bo'ldi?

docker run -it python:3.12-slim buyrug'i quyidagilarni qildi:

1. python:3.12-slim image'ini Docker Hub'dan yuklab oldi (birinchi safar)
2. Bu image'dan yangi container yaratdi
3. Container ichida Python interpretatorini ishga tushirdi
4. -it flaglari orqali sizni container terminaliga uladi

Docker Hub — image'lar do'koni

python:3.12-slim qayerdan keldi? Docker Hub — bu tayyor image'larning ommaviy ombori. Xuddi PyPI (pip) Python paketlar uchun bo'lganidek, Docker Hub image'lar uchun. 

# Mashhur image'lar
$ docker run postgres:16       # PostgreSQL 16
$ docker run redis:7           # Redis 7
$ docker run nginx:latest      # Nginx web server
$ docker run node:20-slim      # Node.js 20
🔄 Django tilida aytganda

pip install django → PyPI'dan Django'ni yuklab oladi
docker run postgres:16 → Docker Hub'dan PostgreSQL'ni yuklab, ishga tushiradi

Farqi: pip faqat Python paketni oladi. docker run — butun muhitni (OS + dastur + sozlamalar) oladi va ishga tushiradi.

Eng kerakli 10 ta Docker buyrug'i

Docker'da yuzlab buyruq bor, lekin kundalik ishda 10 tasi yetarli. Hozircha hammasini yodlash shart emas — bittadan sinab ko'ring.

Buyruq Nima qiladi Misol
docker run Image'dan container yaratib ishga tushiradi docker run nginx
docker ps Ishlab turgan container'lar ro'yxati docker ps
docker ps -a Barcha container'lar (to'xtaganlar ham) docker ps -a
docker stop Container'ni to'xtatish docker stop abc123
docker rm Container'ni o'chirish docker rm abc123
docker images Yuklab olingan image'lar ro'yxati docker images
docker rmi Image'ni o'chirish docker rmi nginx
docker build Dockerfile'dan image yasash docker build -t myapp .
docker logs Container loglarini ko'rish docker logs abc123
docker exec Ishlab turgan container ichida buyruq bajarish docker exec -it abc123 bash

Amaliy mashq: container'lar bilan ishlash

# 1. Nginx web server'ni fonda ishga tushirish
$ docker run -d --name my-web -p 8080:80 nginx
#            ↑     ↑              ↑           ↑
#         fonda  nom berish   port ulash    image

# 2. Tekshirish — brauzerda localhost:8080 oching
# Nginx "Welcome" sahifasi ko'rinadi!

# 3. Ishlab turgan container'larni ko'rish
$ docker ps
CONTAINER ID   IMAGE   STATUS        PORTS                  NAMES
a1b2c3d4e5f6   nginx   Up 2 min      0.0.0.0:8080->80/tcp   my-web

# 4. Container ichiga kirish
$ docker exec -it my-web bash
root@a1b2c3d4e5f6:/# ls /usr/share/nginx/html/
50x.html  index.html
root@a1b2c3d4e5f6:/# exit

# 5. Loglarni ko'rish
$ docker logs my-web

# 6. To'xtatish va o'chirish
$ docker stop my-web
$ docker rm my-web
🔑 Flag'lar eslatmasi

-d = detached (fonda ishlaydi, terminalni band qilmaydi)
-it = interactive + terminal (container ichiga kirasiz)
-p 8080:80 = host'ning 8080 portini container'ning 80 portiga ulash
--name my-web = container'ga odam tushunadigan nom berish

Port mapping — tashqi dunyo bilan aloqa

Container — izolyatsiyalangan muhit. U ichida port 80'da ishlayotgan bo'lsa ham, tashqaridan (brauzerdan) ko'rinmaydi. Port mapping orqali "eshik" ochamiz.

🌐
Brauzer
localhost:8080
→
💻
Host (sizning OS)
port 8080
→
📦
Container
port 80 (Nginx)
# -p HOST_PORT:CONTAINER_PORT

# Nginx (container ichida 80) → brauzerda 8080
$ docker run -d -p 8080:80 nginx

# Django (container ichida 8000) → brauzerda 8000
$ docker run -d -p 8000:8000 my-django-app

# PostgreSQL (container ichida 5432) → host'da 5433
# (agar host'da allaqachon PG 5432 da ishlayotgan bo'lsa)
$ docker run -d -p 5433:5432 postgres:16
🔄 Django tilida aytganda

python manage.py runserver 0.0.0.0:8000 — Django 8000-portda tinglaydi.
Container ichida ham xuddi shunday. Lekin tashqaridan ko'rinishi uchun -p bilan "eshik" ochish kerak. -p 8000:8000 degani: "hostdagi 8000-portga kelgan so'rovni container ichidagi 8000-portga yo'naltir."

Image tanlash: tag'lar va variantlar

Docker Hub'dagi har bir image bir necha tag (versiya) bilan keladi. To'g'ri tag tanlash — production'da muhim. 

# Image nomi formati:
image_nomi:tag

# Misollar:
python:3.12          # To'liq Python 3.12 (Debian-based, ~900MB)
python:3.12-slim     # Kichiklashtirilgan (~150MB) ✅ Tavsiya
python:3.12-alpine   # Eng kichik (~50MB), lekin ba'zi paketlar bilan muammo
python:latest        # Eng oxirgi versiya — ⚠️ ISHLATMANG
⚠️ latest tag'ini ishlatmang

python:latest bugun 3.12, ertaga 3.13 bo'lishi mumkin. Sizning loyihangiz ertaga ishlamay qolishi mumkin va sababini topish qiyin. Har doim aniq versiya yozing: python:3.12-slim

Tag turi Hajmi Qachon ishlatiladi
3.12 (to'liq) ~900 MB C extension'lar ko'p bo'lganda
3.12-slim ✅ ~150 MB Aksariyat Django loyihalar uchun
3.12-alpine ~50 MB Hajm muhim bo'lganda (lekin ehtiyot bo'ling)

🏗️ Mustaqil mashq

Quyidagilarni terminalda bajarib, natijalarini ko'ring. Har bir buyruqdan keyin docker ps va docker ps -a bilan holatni tekshiring.

  1. docker run hello-world — Docker o'rnatilganini tekshiring
  2. docker run -it python:3.12-slim — Python container ichida 2 + 2, import this yozing, keyin exit()
  3. docker run -d --name test-nginx -p 9090:80 nginx — Nginx'ni ishga tushirib, brauzerda localhost:9090 oching
  4. docker exec -it test-nginx bash — container ichiga kiring, cat /usr/share/nginx/html/index.html bilan sahifani ko'ring
  5. docker logs test-nginx — loglarni ko'ring
  6. docker stop test-nginx && docker rm test-nginx — tozalab tashlang
  7. docker images bilan yuklab olingan image'larni ko'ring. docker rmi hello-world bilan keraksizini o'chiring.
